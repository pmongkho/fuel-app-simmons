# Production SQL / backend maintenance notes

This backend uses ASP.NET Identity and stores application users in `AspNetUsers`.
That means **emails can be updated directly with SQL**, but **passwords must use a valid ASP.NET Identity password hash**.

## 1) Create an app user directly in PostgreSQL

```sql
INSERT INTO "AspNetUsers" (
    "FullName",
    "Role",
    "IsActive",
    "CreatedAtUtc",
    "UserName",
    "NormalizedUserName",
    "Email",
    "NormalizedEmail",
    "EmailConfirmed",
    "PasswordHash",
    "SecurityStamp",
    "ConcurrencyStamp",
    "PhoneNumberConfirmed",
    "TwoFactorEnabled",
    "LockoutEnabled",
    "AccessFailedCount"
)
VALUES (
    'Production Admin',
    2,
    TRUE,
    NOW() AT TIME ZONE 'UTC',
    'admin@example.com',
    'ADMIN@EXAMPLE.COM',
    'admin@example.com',
    'ADMIN@EXAMPLE.COM',
    TRUE,
    '<ASP.NET_IDENTITY_PASSWORD_HASH>',
    gen_random_uuid()::text,
    gen_random_uuid()::text,
    FALSE,
    FALSE,
    FALSE,
    0
);
```

Role values used by the backend:

- `0` = `Employee`
- `1` = `Supervisor`
- `2` = `Admin`

> `PasswordHash` must be generated by ASP.NET Identity. For production password changes, prefer the admin backend endpoint shown below instead of hand-writing hashes.

## 2) Delete all rows from an app table

Example for one table:

```sql
DELETE FROM "FuelReports";
```

If you want PostgreSQL to reset the identity sequence too:

```sql
TRUNCATE TABLE "FuelReports" RESTART IDENTITY CASCADE;
```

## 3) Remove all existing seeded/demo data

This clears the current demo trailers, reports, email logs, recipients, and demo users.

```sql
BEGIN;

TRUNCATE TABLE "FuelEntryPhotos" RESTART IDENTITY CASCADE;
TRUNCATE TABLE "FuelEntries" RESTART IDENTITY CASCADE;
TRUNCATE TABLE "FuelReports" RESTART IDENTITY CASCADE;
TRUNCATE TABLE "EmailLogs" RESTART IDENTITY CASCADE;
TRUNCATE TABLE "NotificationRecipients" RESTART IDENTITY CASCADE;
TRUNCATE TABLE "Trailers" RESTART IDENTITY CASCADE;

DELETE FROM "AspNetUsers"
WHERE "Email" IN (
    'employee@fuelapp.local',
    'employee2@fuelapp.local',
    'employee3@fuelapp.local',
    'supervisor@fuelapp.local',
    'admin@fuelapp.local'
);

COMMIT;
```

## 4) Change a user's email

Because ASP.NET Identity normalizes both `Email` and `UserName`, update all four columns together.

```sql
UPDATE "AspNetUsers"
SET
    "Email" = 'new-email@example.com',
    "NormalizedEmail" = 'NEW-EMAIL@EXAMPLE.COM',
    "UserName" = 'new-email@example.com',
    "NormalizedUserName" = 'NEW-EMAIL@EXAMPLE.COM'
WHERE "Id" = 1;
```

## 5) Change a user's password

### Preferred backend route

Use the new admin endpoint so the backend generates the correct ASP.NET Identity hash:

```bash
curl -X PUT "https://your-api.example.com/api/users/1/password" \
  -H "Authorization: Bearer <ADMIN_JWT>" \
  -H "Content-Type: application/json" \
  -d '{"newPassword":"NewStrongPass123"}'
```

### If you must do it with SQL

First generate a valid ASP.NET Identity hash in application code, then store it with SQL:

```sql
UPDATE "AspNetUsers"
SET
    "PasswordHash" = '<ASP.NET_IDENTITY_PASSWORD_HASH>',
    "SecurityStamp" = gen_random_uuid()::text,
    "ConcurrencyStamp" = gen_random_uuid()::text,
    "AccessFailedCount" = 0,
    "LockoutEnd" = NULL
WHERE "Id" = 1;
```

## 6) Change a user's email through the backend

```bash
curl -X PUT "https://your-api.example.com/api/users/1/email" \
  -H "Authorization: Bearer <ADMIN_JWT>" \
  -H "Content-Type: application/json" \
  -d '{"email":"new-email@example.com"}'
```

## 7) Production note

Automatic startup seed data has been removed from `Program.cs`, so a production deploy will only run EF Core migrations and will not recreate demo users or records.
